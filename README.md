# AGRIXON

Local-first crop-rotation and field-monitoring workspace built on NASA open data.
This repository contains the source for the Windows **0.4.2** build.

## Requirements

- Node.js 20 or newer (the Windows build embeds Node.js 22).
- No `npm install` is needed to run the existing build.
- `npm install` is only needed to rebuild the bundled server/client or to run the
  Playwright browser harness.

## Quick start

```bash
npm start
# equivalent: node server-tools.mjs
```

Open <http://localhost:3000/tools>. The base workspace is at
<http://localhost:3000/>.

`server-tools.mjs` is the real entry point: it serves `/tools`, the METOS and
weather proxies, sensor ingestion, and delegates everything else to
`server.mjs`. To run only the base server:

```bash
npm run start:base
# equivalent: node server.mjs
```

Stop the server with `Ctrl+C`.

## Tests

```bash
npm test
```

This runs 19 backend/route tests and 6 UI-model tests. The browser regression
harness in `validation/browser-regressions.mjs` is a Playwright snippet and is
not part of `npm test`; it needs a running server and Playwright.

## Source layout

| Path | Purpose |
| --- | --- |
| `server-tools.mjs` | Tools/METOS/weather/sensor server; real entry point |
| `server.mjs` | Bundled base server (NASA proxies, workspace, static allowlist) |
| `prelude.mjs` | Runtime paths, packaged-exe data directory, LAN defaults |
| `public/` | Current frontend: map, tools, sensors, 3D diorama, styles |
| `public/app.js` | Built/minified client bundle |
| `source/AppName-live/` | TypeScript source for the client and Node adapter |
| `source/crop-rotation/` | Agronomic core and NASA API route sources |
| `build.mjs` | Rebuilds `server.mjs`, `server-tests.mjs`, `public/app.js` |
| `ui-tests.mjs` | UI-model tests (DEM zoom, GDD, growth model) |
| `server-tests.mjs` | Bundled backend/route tests |
| `validation/` | Test logs, METOS stage notes, browser regression harness |

`public/field3d.js`, `public/field-model.js`, `public/nav.js` and
`public/redesign.css` are hand-written modules and are not generated by
`build.mjs`.

## Rebuild

```bash
npm install
npm run build
```

`build.mjs` uses esbuild and the TypeScript sources under `source/`. It writes
`server.mjs`, `server-tests.mjs` and `public/app.js`.

## Windows executable

The release asset `AGRIXON-Windows-0.4.2.zip` contains `AGRIXON.exe`, a bundled
Node.js runtime, `public/`, `START.bat` and diagnostics. To rebuild the exe:

```bash
npm install
npx @yao-pkg/pkg server-tools.mjs --targets node22-win-x64 --compress GZip --output AGRIXON.exe
```

The `pkg.assets` list in `package.json` embeds `public/**/*` and
`sensors.config.json`. It deliberately does **not** embed `.env.local`.

## Configuration and secrets

Copy `.env.example` to `.env.local` and fill only the values you need:

```bash
cp .env.example .env.local
```

Never commit `.env.local`, `.sensors.json`, `.telegram.json`, `.metos.json` or
`.workspace-snapshot.json`. They are ignored by `.gitignore`.

- FIRMS: `FIRMS_MAP_KEY`
- Telegram: `TELEGRAM_BOT_TOKEN`
- METOS/FieldClimate: enter the Public Key and Private Key in
  `/tools → METOS stations`; they are stored locally, not in the browser.
- Sensor ingest: optional `SENSOR_KEY`.

The packaged Windows exe stores writable data in `%LOCALAPPDATA%\AGRIXON`.
Running from source stores it next to `server-tools.mjs`.

## Data sources and honesty

- Map: MapLibre; OpenFreeMap basemap through the local proxy.
- NASA POWER, GIBS, Worldview, EONET and CMR need no key.
- NDVI is an imagery layer, not crop identification or a field measurement.
- Missing data is shown as an explicit status, never as zero.
- The 3D stage/height model is an estimate, not a measurement.
- METOS live authentication and payload compatibility still need verification
  with an authorized FieldClimate account.
- Planet Labs, BBLeap and John Deere integrations require separate accounts or
  partnerships and are not included.

## Limitations

- The Windows exe is unsigned and has not been run on a live Windows machine.
- METOS was verified with fixture responses, not a live station.
- The full precision-agriculture feature list is not implemented; see
  `validation/2026-11-14-metos-sync.md` for the current stage and limits.
