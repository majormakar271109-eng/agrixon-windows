Прямые проверки через отдельный веб-доступ дали ответы POWER (6 параметров, 06.10–04.11.2026), EONET (валидный пустой список), CMR (коллекция MOD13Q4N), GIBS (изображения NDVI/True Color за 04.11.2026) и Worldview (изображение за 06.06.2025). Это НЕ проверка полного сетевого пути локального приложения. Формат и заполненность пикселей не измерялись по веб-описаниям изображений.

В среде приложения реальный Node.js fetch к NASA и OpenFreeMap завершается ENOTFOUND: DNS не разрешает адреса. Проверка живой цепочки локальный сервер → NASA НЕ пройдена. FIRMS не проверен: нужен собственный серверный MAP_KEY.

Исправлено: сообщения DNS/таймаута/HTTPS теперь различаются; названия исходных моделей POWER, единицы параметров и временной стандарт берутся из ответа. Убрана неверная фиксированная подпись MERRA-2/CERES для свежих данных GEOSIT/FLASHFLUX. Пропуски -999 остаются null.

## Проверка на вашем компьютере
1. Запустите START.bat и оставьте окно открытым.
2. Запустите CHECK_NASA.bat в той же папке (либо node check-nasa.mjs).
3. Получится nasa-diagnostics.json с HTTP-статусами, кодами ошибок, количеством записей и результатом проверки PNG/JPEG. Скрипт обращается к реальным локальным API, не использует фикстуры, не показывает ключ FIRMS. Он не подменяет NASA другим сервисом.
4. Если есть ошибки, пришлите nasa-diagnostics.json. В случае другого порта: node check-nasa.mjs 3001.

При недоступной сети или источнике скрипт завершается с кодом 1; отсутствие ключа FIRMS помечается отдельно. Изображение с прозрачными пикселями может иметь корректный формат: тест формата не гарантирует наблюдений над каждым полем. Результат не доказывает отрисовку WebGL-карты браузером.
